## 완료된 설계 결정 요약

### 1–2단계: 범위와 도구

- 초기에는 **허용 프로젝트 1개**, 이후 명시적 설정을 통해 확장 가능.
- 일반 프로젝트 파일은 민감 경로를 제외하고 탐색·검색·읽기 허용.
- **쓰기 허용 디렉터리 안에서는 파일 형식에 관계없이 생성·수정 권한**을 부여하되, 첫 구현·검증은 텍스트 파일 중심.
- 쓰기 허용 디렉터리 바깥은 명시적 **예외 파일**만 생성·수정 허용 (`AGENTS.md`, `README.md` 등).
- 삭제·이동·임의 명령 실행·범용 소스 쓰기 도구는 MVP에서 제외.
- **최종 MCP Tools 7개:** `list_files`, `search_text`, `read_file`, `create_file`, `edit_file`, `preview_edit`, `apply_edit`.

### 3단계: 접근 제어

- [x] 프로젝트 루트는 로컬 **YAML 설정 Allowlist**로 지정; MCP 입력은 상대경로만 허용.
- [x] 쓰기 디렉터리 + 예외 파일을 설정; 설정 변경은 서버 재시작 시 반영.
- [x] **내장 Denylist + 사용자 차단 규칙 추가**; 민감 경로는 읽기·검색·생성·수정 모두 금지.
- [x] 프로젝트 외부와 **심볼릭 링크 경유 경로** 차단.
- [x] 실제 접근 전 공통 Policy에서 매번 검사; `.gitignore`는 보안 통제의 대체물이 아님.

### 4단계: 수정·저장 안전성

- [x] 기본 작업은 ChatGPT **쓰기 도구 승인 후 수정**; Ubuntu 별도 승인 UI는 도입하지 않음.
- [x] `preview_edit`은 **선택적** 채팅 Diff 미리보기; `apply_edit`은 메모리에 저장된 동일 수정안만 적용.
- [x] `read_file`의 **SHA-256 원본 해시**를 수정 요청에서 필수로 확인; 충돌 시 거부, 자동 병합 없음.
- [x] 동일 파일에 대한 **MCP 내부 쓰기 직렬화**.
- [x] 수정은 **같은 디렉터리의 임시 파일 작성 후 원자적 교체**를 목표로 함.
- [x] 새 파일 생성은 기존 파일이 있으면 거부; 생성·수정 모두 동일한 범위 권한 적용.
- [x] TDD 및 실제 VS Code 저장 충돌을 포함한 검증 기준 결정.
- [x] 외부 Codex/VS Code와의 TOCTOU 경쟁 조건을 **완전히 제거했다고 가정하지 않음**.

### 5단계: 기술·아키텍처·테스트·운영

- [x] **Node.js 24 + TypeScript ESM + 공식 MCP SDK v2**.
- [x] **Zod v4, Vitest, Oxlint, Oxfmt**, 내장 `fs`/`path`/`crypto` 우선; 추가 라이브러리는 필요할 때만.
- [x] **stdio**: `tunnel-client` 프로필의 `mcp-command`가 빌드된 MCP 서버를 실행; Express/HTTP 서버 불필요.
- [x] 역할별 모듈 분리: `tools`, `policy`, `files`, `config`, `preview`, `audit`.
- [x] YAML 설정은 서버 시작 시 검증하고 프로젝트 바깥에 보관.
- [x] npm **정확한 버전 + `package-lock.json`**, `tsc` 빌드 후 Node.js 실행.
- [x] 테스트: 단위 → 로컬 파일시스템 통합 → MCP stdio 통합; 실제 터널은 7단계 검증.
- [x] **기능별 수직 TDD:** 정상 경로 RED → GREEN → REFACTOR → 실패·보안 검증.
- [x] 경쟁 조건은 테스트 지점에 변경을 주입해 재현; 반복 동시 실행은 보조 검증.
- [x] 디렉터리: `~/repos/gpt-helper-mcp/` (소스), `~/tools/tunnel-client/` (터널), `~/.config/personal-mcp/` (정책), `~/.local/state/personal-mcp/` (로그).
- [x] 진단은 `stderr`, 감사 기록은 **민감 내용을 제외한 JSONL**.
- [x] `start-mcp.sh`에서 터널용 `.env`를 로드하고 수동 시작·종료·재시작. 자동 재시작·자동 키 갱신은 제외.
- [x] API 키 보관 `.env`는 **계획만 확정**, 아직 실제 파일·권한 설정은 하지 않음.
- [x] 개발은 Codex 중심, **최초 MCP 서버 및 읽기 도구는 직접 구현 가능**하게 작업 분할.
- [x] 별도 **설계·구현 인계서(SSOT)** 작성.
